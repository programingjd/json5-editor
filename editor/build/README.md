# Browser compatibility adapters

These scripts are Vite plugins that modify the JavaScript glue generated by
wasm-bindgen for the GPUI editor. They are handwritten source files, not build
output, and must be committed.

The shared configuration in [`../vite.config.mjs`](../vite.config.mjs) applies
them before bundling, for both development and production, in the standalone
app and browser extensions. They transform the generated module in memory;
they do not edit the generated files on disk or modify the WASM binary.
This keeps the adjustments reproducible when a WASM rebuild regenerates the glue.

## `wasm-csp.js`

Replaces the generated JavaScript evaluator used by `wasm_thread` to look up
`self`. That specific expression returns `globalThis` instead, without calling
`eval`. Any other expression raises an error rather than being evaluated.

Manifest V3 extension pages forbid JavaScript evaluation, even when they allow
WebAssembly. This adapter makes the dependency's global-object lookup compatible
with that restriction. The build also fails if an unsupported `eval` call remains.

## `browser-gpu-defaults.js`

Removes `powerPreference` from the options passed to WebGPU's `requestAdapter`,
preserving the other options.

The pinned GPUI renderer requests a high-performance GPU. The editor leaves
adapter selection to the browser instead, avoiding an explicit preference for
a discrete GPU just to display JSON. This also avoids the warning on Windows
that the supplied power preference is ignored.

## `browser-clipboard.js`

Redirects the generated clipboard `writeText` call to
[`../src/clipboard.js`](../src/clipboard.js), adding an import for that helper.
The helper defers clipboard access until the current Rust callback has finished.
It uses the Clipboard API when available and falls back to a temporary textarea
and `execCommand('copy')` when the API is missing or permission is denied.
The fallback restores the previous DOM selection and focus afterwards.

Native clipboard operations can synchronously move focus and re-enter GPUI
while Rust state is still borrowed, causing `RefCell` errors. Deferring the
operation avoids that re-entry. The fallback is needed in Firefox extension
viewers embedded in HTTP response pages, where `navigator.clipboard` can be absent.

## `browser-input-focus.js`

Redirects the generated DOM `focus` call to
[`../src/browser-input-focus.js`](../src/browser-input-focus.js), adding an
import for that helper. It records GPUI's hidden textarea and restores DOM
focus to it if Firefox subsequently focuses the canvas. The handoff runs in
a microtask, after the native focus event and Rust callbacks finish, and respects
later focus changes, inactive documents and elements marked `inert`.

GPUI draws both the document and search fields on a canvas, but its keyboard
and composition listeners are attached to the hidden textarea. When Firefox
focuses the canvas instead, mouse commands still work while all keyboard input
stops. Restoring the textarea's DOM focus preserves GPUI's internal choice of
caret or search field without synchronously re-entering a borrowed Rust window.

## Dependency updates

The GPU, clipboard and focus adapters require exactly one occurrence of their
expected generated binding and fail the build if its shape changes. When updating
GPUI or wasm-bindgen, inspect the regenerated glue and review these adapters;
do not bypass the checks or edit the generated JavaScript by hand.
